# AVAILABLE 2.0 Documentation

This folder is the self-contained documentation package. It includes the current
guides, figures, MkDocs configuration, and documentation-only dependencies. It
does not require the application, a training corpus, Azure, Qdrant, or Opik to
build or preview the website.

## Layout

```text
docs/
  README.md
  mkdocs.yml
  requirements.txt
  .gitignore
  content/
    index.md
    getting-started/
    user-guide/
    architecture/
    operations/
    deployment/
    development/
    reference/
    assets/figures/
  site/                 generated by a build; ignored by Git
```

Edit Markdown and figures under `content/`. Add navigation entries in
`mkdocs.yml`. Do not edit generated HTML under `site/`.

## Install Documentation Tools

From the repository root, using an installed Python 3.11 interpreter:

```powershell
Set-Location docs
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Installing tools requires access to an approved Python package index. If the
dependencies are already installed in your selected environment, use its
`python -m mkdocs` directly instead of creating another environment. The pinned
versions match the environment used to validate this documentation package.

## Preview and Build

From `docs`:

```powershell
.\.venv\Scripts\python.exe -m mkdocs serve --dev-addr 127.0.0.1:8000
```

Open <http://127.0.0.1:8000>. If the port is occupied by another preview, use
`--dev-addr 127.0.0.1:8001`. Stop the preview with Ctrl+C.

Build the website and validate links:

```powershell
.\.venv\Scripts\python.exe -m mkdocs build --strict
```

The output is `docs/site/`. All source paths are relative to the configuration
inside this folder; the old `documentation/` directory and
`dc-available/mkdocs.yml` are not needed to build this package.

## Documentation-Only Contribution

Include this folder's source files, images, configuration, requirements, and
`.gitignore` in a documentation-only change. Generated `site/` and `.venv/` are
ignored. Review the selected files before committing; other local application
or deployment changes do not belong in that change.

Branch creation, staging, commits, and pushing are separate manual actions. None
are performed by the documentation preview or build commands. No hosting or
automatic publishing workflow is configured here.

The older documentation and deployment history remain at their original
locations in the development workspace. This package contains the curated site,
not copies of the old code walkthroughs or research drafts. The
[maintenance guide](content/development/documentation.md) records the source
material and known figure caveats. Use `docs/content` for future site edits.

Review the Opik screenshot and corpus-derived examples with the content owner
before publishing outside the authorized audience. The site deliberately avoids
external font loading, but documentation about the application includes external
service links and commands; those are not executed by building this website.
